# 04：用真实失败场景做四轮有界对照

状态：WAITING_GATE。01–03通过；最多4轮冷启动或2小时，先到即停止。

先读 [总任务书](00_taskbook.md)。本文件是待执行任务，本次复核没有执行这些修改。


## 只做这些

1. 从旧失败日志固定“单窗口W2停止”和“双窗口about:blank”两种复现命令/顺序；使用已有官方页面和参数。现有六轮只跑x4单窗口，不足以覆盖双窗口故障。不要增加新的GPU/SMP/GIC/zygote参数扫描。
2. 两种场景各做trace-on/off一次，共4轮，预定交错顺序；保留所有请求。不做reload/restart掩盖首次失败。trace-on需要写入违规为0才允许事件因果分析；trace-off失败也不能用另轮正常trace证明已定位。
3. 使用01的实际页面契约和02的真实终态。进展看预声明阶段标记和时间，而不是单一色数或QMP running。CDP超时仅算观测/页面通道疑点，不能直接算全客机死锁。
4. 真正失去推进时先冻结并保存原始环和状态，再发可能扰动现场的客机诊断命令；记录触发到冻结间隔、各CPU保留窗口。关键事件已丢失就写缺证据，不能把空缺当丢IRQ。

完成后的分流（必须选一条，不再无期限等待复现）：

- 四轮均达各自验证范围且无可信失败：进入05的候选验收，结论是“此候选未复现历史问题”，不声称根因已修复。
- 任一可信失败：保留最早样本，停止剩余重复，进入06；工具失败先只回02，最多修一次再重开新批次。
- 只有观察工具缺证据：标INCOMPLETE并说明缺口，不把它计入成功或内核失败，不擅自扩批。
