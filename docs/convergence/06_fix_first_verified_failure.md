# 06：只修最早一个可证实的失败

状态：CONDITIONAL。仅04或05出现可信失败时执行；每个假设最多4小时。

先读 [总任务书](00_taskbook.md)。本文件是待执行任务，本次复核没有执行这些修改。


## 分支与完成点

1. DOM/窗口失败但客机仍推进：检查同一时刻的URL、文档结构、窗口目标、renderer及服务状态，定位浏览器/窗口提交阶段；先排除页面契约与观测错误，不直接改timer。
2. 全客机失去推进：核对同版本冻结事件、最后完整timer/IPI/入队/调度链和寄存器/IRQ状态。事件时间相邻且arg0/arg1全0只证明发生过，不能凭此绑定同一任务的因果链；只补定位所需的一个关联字段。
3. 记录器writer违规、ring损坏或关键窗口丢失：先修这一明确取证缺口，旧根因结论保持未知；不回头重写已通过的全套工具。
4. 每轮只做一个有证据的最小修复、一个可否证对照及针对性回归。超过4小时仍未知，交接首个未知边界与下一条最小实验；不换参数堆批次，不将跟踪器修复冒称浏览器停顿修复。

交付：first-failure.md、同版本证据和最小diff。短验证后返回04/05；没有可信失败时此任务应SKIPPED_CONDITIONAL，不阻塞主线。
