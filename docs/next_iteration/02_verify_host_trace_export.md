# 02：验证不依赖客机命令的内存取证

优先级：P1。开始条件：01通过后可做短会话验证；建议2–4小时。

工作目录：`D:\x-kernel-dsh-bridge\submission\for github`。本文件是待执行任务，不是完成记录。

执行前先读 [总计划及统一交付规则](00_review_and_plan.md)。


## 为什么现在做

全客机停顿后shell命令不再返回，因此仅设计“客机执行脚本导出”无法闭环。上一轮 `-d int` 单轮产生284,888,462字节，仍没有所需事件轨迹。先证明宿主能读到一个小的已知记录，再上内核事件环。

## 本次只做

1. 检查本机QEMU实际支持的只读取证接口、当前内存布局与已有宿主连接封装。优先复用现有接口；不为了导出先修改调度器或增加长期高频串口输出。
2. 在明确地址放置/选择一个可校验的小记录：magic、schema、boot nonce、长度、校验值。对照ELF符号、加载段、实际启动地址和虚拟/物理转换，给出地址来源链。若须新增探针，范围仅此记录，单独构建留bin/ELF/config哈希。
3. 在一个正常诊断会话读取两次；宿主停止vCPU后再次读取并校验。测试不能把“QMP显示running”直接当客机仍推进。

## 验收

一条固定宿主命令可在客机shell不可用时导出该记录；正常态和宿主停止态都能校验版本、nonce与字节数；无效地址/错版本明确报错。输出 `export-contract.json`，含地址计算、命令、停机规则和局限。

注意：01的比较脚本中 `0x10000` 是ELF与裸bin的文件偏移差；不是客机物理加载地址。旧PC映射必须先证明对应bin/ELF，不能拿旧procfs轮次和新ELF直接连线。

此任务只证明取证通道，不算真实卡死定位成功。导出单文件暂定上限1MiB；容量不足先解释字段预算，不开启无界追踪。
