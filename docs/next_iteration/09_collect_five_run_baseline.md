优先级：GATE。开始条件：07实现与08候选门槛通过。

工作目录：`D:\x-kernel-dsh-bridge\submission\for github`。本文件是待执行任务，不是完成记录。

执行前先读 [总计划及统一交付规则](00_review_and_plan.md)。


## 本次只做

1. 以08冻结候选作为当前可复测基线，连续记录至少5轮完整有效样本，每轮同时输出首帧区间、独立页面加载、角色可证的renderer创建/发现延迟、客机总占用采样峰值。保存全部尝试与失败，不把不同轮次空字段拼齐。
2. 原始字段包括run/boot ID、bin/ELF/config/page哈希、QEMU/宿主信息、时间源、间隔、单位、缺失原因、退出码和日志路径。采样窗口覆盖声明的启动与指定负载过程。
3. 输出中位数、最小/最大、首帧区间及不确定度；检查异常值原因，不能为了降低波动删点。区间数据不计算伪精确的改善百分比。
4. 追溯赛题要求的“首个可运行版本”代码和原始数据。将历史基线与当前诊断/测量基线分开命名；缺少可重建代码就写明缺口，不能事后造一个历史tag来证明已存档。

## 验收

四项各n>=5，且来自同一组完整轮次；独立汇总脚本可从原始数据重算。旧4轮17.56085秒中位数和约50–60秒首帧区间继续保留，只作旧集重解析；它们不是新增轮次，更不能凑第5轮。

沿用用户确认约840MB客机总占用作为预算依据，不再把历史内存争议作为全任务阻塞。这里补的是新候选同轮数据；抽样最大值需注明频率，不称连续时间的精确峰值。最终现场资格与排名依统一脚本。
