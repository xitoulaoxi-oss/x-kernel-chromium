# 04：保留中途导出失败的全部证据

开始条件：可独立实现；最终用01/02新环验证。预计1–2小时。

状态：READY；本文件为待执行任务。先读 [总任务书与日志规则](00_taskbook.md)。


## 剩余边界

ring_capture正常模式已冻结、校验并按4KiB读取。但partial变量只累加header；全量循环中已经成功读取的块在后续出错时可能丢失。--resume分支在finally执行，结果报告在finally之后写盘，与契约“写完报告后恢复”存在次序差异。

## 工作与验收

1. 成功读取的每块都进入有界partial证据和长度/地址清单；第2块或最后块短读、断连、写文件失败时，报告阶段、已取得字节及原始哈希。
2. 先持久化raw/失败报告，再处理明确恢复请求；默认保持paused，原本paused的客机保持paused。恢复失败另记录，不能覆盖原始取证失败。
3. 区分头部有效、完整传输、解码有效与恢复状态；结构有疑点时保留dump，不以自动恢复或退出清理掩盖现场。
4. 用可控QMP响应/文件写入负例验证，不为了错误路径反复启动完整浏览器；至少一条正常新环导出验证地址和schema。

交付：故障注入测试、契约/代码一致的次序、完整partial报告。旧wrong-symbol测试仍保留，是头部错误场景，不能代替中途短读测试。
