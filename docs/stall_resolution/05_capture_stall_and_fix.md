# 05：捕获真实停顿并做一个可解释修复

开始条件：01–04通过；每个假设预算4–8小时。

状态：WAITING_GATE；本文件为待执行任务。先读 [总任务书与日志规则](00_taskbook.md)。


## 工作与验收

1. 固定新诊断bin/ELF/config/页面/rootfs/QEMU参数，预声明首次启动、心跳停止和触发窗口。所有QEMU实验串行；保留正常与失败的全部尝试，不用reload/restart补首次启动。
2. 至少一轮正常、一轮真实全客机停顿，同版本独立冻结导出。记录QMP running/paused、串口推进、硬件counter与宿主CPU，区别“控制通道故障、浏览器无窗口、文档未提交、全客机停顿”。
3. 首先证明记录器本身没有破坏轨迹，关键时间窗未覆盖丢失。写最后确认事件→应有事件→实际缺失/异常→替代解释；没有足够证据就缩小定位范围，不直接宣称丢IRQ/IPI。
4. 只改一个有证据支持的边界，保存相同条件before/after和针对性回归；100ms fallback仍是未充分修复的历史候选，不能继续盲调tick换通过。

交付：causal-chain.md、原始dump及哈希、版本索引、最小补丁与验证。没复现也交付有效运行账本和下一可证伪假设，不启动20次/五轮来掩盖定位不足。
